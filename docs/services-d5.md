# سياسة الخدمات والدعم والموافقات — D5

## الملخص

D5 يضيف ثلاثة نطاقات فوق ما سبق:

1. **الخدمات والفترات** — أنشطة وخدمات (ترفيه، إنترنت، تغذية، رياضة) يملكها ضباط، مع فترات تسجيل زمنية وسعة محسوبة بدقة تحت التزامن.
2. **الشكاوى والصيانة** — الطالب يقدّم شكوى (إدارة السكن تنظرها) وطلب صيانة (مسؤول الصيانة يعالجه)، بحالات موثّقة ونص معالجة إلزامي.
3. **الإذن والغياب والبلاغات الطارئة** — إذن غياب (شؤون الطلاب توافق/ترفض)، بلاغ خروج طارئ (يُوثّق الخروج ثم يُغلق)، وسجل غياب يُبنى من الاثنين فقط.

## الأدوار والصلاحيات

مصفوفة ثابتة في الكود (لا جداول أدوار):

| الدور | النطاق |
|---|---|
| Activity Officer | خدمات الترفيه والإنترنت (إنشاء/تعديل/فترات) |
| Food Officer | خدمات التغذية |
| Sports Officer | خدمات الرياضة |
| Housing Administration | شكاوى الطلاب (مراجعة/حل/إغلاق) |
| Maintenance Officer | طلبات الصيانة (إسناد/تنفيذ/حل/إغلاق) |
| Student Affairs | موافقة/رفض إذن الغياب، وتوثيق الخروج الطارئ |
| Student | التسجيل في الفترات المفتوحة، تقديم الشكاوى والطلبات، إلغاء تسجيله |

## قواعد الخدمات والفترات

- كل خدمة يملكها دور ضابط **بُحسب نوعها** (`managed_by_role`)، ويُفحص **في كل عملية** على الخدمة — الضابط الأجنبي يُرفض (403).
- اسم الخدمة فريد لكل نوع (`service_type` + `name`)، ويمكن تعطيل الخدمة فتُمحى فتراتها الجديدة.
- دورة الفترة: `Upcoming → Open → Closed → Completed`، مع **فتح/إغلاق** كخطوة عكسية وحيدة (إعادة الفتح مسموحة).
- التسجيل يُقبل **فقط** والفترة `Open`، ومرة واحدة لكل فترة (قيد تفريد)، مع بقاء مقعد:
  - فحص التسجيل المسبق يسبق فحص السعة (المكرر يجيب 409 «مسجل مسبقاً» وليس 422).
  - السعة `NULL` تعني غير محدودة.
- الإلغاء يُبدأ **بالطالب** ويُحفظ في السجل؛ الضباط لا يحذفون التسجيلات أبداً.
- الأهلية: ملف طالب كامل، وليس موقوفاً/منهياً (حالة السكن هي المرجع).

### الضمان تحت التزامن

القسم الحرج كله يعمل في معاملة واحدة مخصصة يحرسها **قفل MySQL مسمى** + **قفل صف `FOR UPDATE`** على الفترة:

- الخاسر في سباق التسجيل يحصل على 422 نظيف «الفترة ممتلئة» (لا يتجاوز أحد السعة: [201, 422] في اختبار خيطين).
- قفل MySQL المسمى مُرتبط بالاتصال **ويعيش بعد commit/rollback**، لذا يُحرَّر في `finally` **داخل** المعاملة نفسها قبل عودة الاتصال للمجمع (أي مسار خطأ 409/422 لا يتركه عالقاً)، بينما يبقى قفل صف الفترة حتى الالتزام، فيُؤمّن العَدّ حتى لمن يلتقط القفل المسمى مباشرة بعد التحرير.

## الشكاوى والصيانة

- الشكوى: `Open → Under Review → Resolved → Closed`، نص المعالجة **إلزامي** لإنهاء/إغلاق، لا حذف.
- الصيانة: `Pending → Assigned → In Progress → Resolved → Closed`، الغرفة (إن وُفّرَت) يجب أن تكون **إقامة الطالب النشطة حالياً**؛ بلا إقامة نشطة لا يجوز إرفاق غرفة.
- الطالب يرى سجلاته فقط؛ الضابط يرى سجل نطاقه كاملاً. الصفحات مرقّمة وقابلة للتصفية بالحالة.

## الإذن والغياب والبلاغات الطارئة

- إذن غياب: `Pending → Approved / Rejected / Cancelled` (الإلغاء من الطالب قبل القرار).
- الموافقة على الإذن تُنشئ غياباً من نوع `permission` بنفس الفترة ومصدر `permission:<id>`.
- البلاغ الطارئ: `Reported → Under Review → Verified → Closed`؛ التوثيق (`verify`) يضع `exit_verified=True` **ويعندئذ فقط** يُنشأ غياب من نوع `emergency` (قاعدة 9.2: البلاغ ليس غياباً حتى يوثّق الخروج)، والإغلاق يبقيه.
- الغياب غير المصرّح لا يُنشأ في هذه الدفعة (عمل يدوي/ضابط لاحقاً).

## واجهة API

| المسار | العمليات |
|---|---|
| `/services`, `/services/{id}` | إنشاء/تعديل الخدمات (الضابط المالك) |
| `/service-periods`, `/{id}/status`, `/{id}/registrations` | الفترات وفتح/إغلاق وقائمة التسجيلات |
| `/service-registrations`, `/me`, `/{id}/cancel` | تسجيل الطالب وعرضه وإلغاؤه |
| `/complaints`, `/my`, `/{id}/action` | طلب ومتابعة، وعمل المراجعة (Housing) |
| `/maintenance`, `/my`, `/{id}/action` | طلب ومتابعة، وعمل المعالجة (Maintenance Officer) |
| `/permissions`, `/my`, `/{id}/decision`, `/{id}/cancel` | طلب إذن، القرار (Student Affairs)، والإلغاء |
| `/emergency`, `/my`, `/{id}/action` | بلاغ طارئ، وتوثيق/إغلاق |
| `/absences`, `/my` | سجل الغياب (من الإذونات والبلاغات) |

## التدقيق

كل عملية كتابة تُسجَّل في `audit_events` في **نفس المعاملة**؛ فشل كتابة السجل يلغي التغيير. الأنواع الجديدة: إنشاء/تعديل خدمة وفترة، تسجيل/إلغاء، قرارات الشكاوى والصيانة، قرار الإذن، توثيق البلاغ، توليد الغياب.

## ما لا يفعله D5 (في هذه الدفعة)

- **تسليم الإشعارات**: الجدول والنموذج `notifications` جاهزان في قاعدة البيانات (عنوان، نص، حالة، وقت القراءة)، لكن واجهة API والواجهة الأمامية **مؤجلتان**.
- الغياب غير المصرّح وسجلّات الحضور اليومي (عمل ضباط لاحق).
- لوحات معلومات الضباط، وذكاء تنظيف (BFS/A*) — دفعات لاحقة.
- تسجيل عام أو إنشاء حسابات ذاتي — يبقى System Administrator مصدر كل الحسابات (من D1/D2).
