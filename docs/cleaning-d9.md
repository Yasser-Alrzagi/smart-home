# D9 — تنظيف الذكاء: توزيع مهام النظافة بـ BFS و A*

الدفعة الأخيرة: **دورة نظافة** لطابق (فترة تواريخ) يُوزّع عملها تلقائياً على الطلاب المقيمين بخوارزميتين قابلتين للمقارنة — **BFS** و **A*** — ثم الاعتماد والتفعيل والتنفيذ، ضمن مخطط `cleaning_cycles` و`cleaning_assignments` و`ai_optimization_runs` المعتمد منذ D1.

## 1. طريقة العمل

1. **مسؤول النظافة** ينشئ دورة: طابق + تاريخ بداية ونهاية (`Draft`).
2. **التشغيل**: `BFS` أو `A*` — كل تشغيل يُخزَّن كسجل `AIOptimizationRun` بمقاييسه (التكلفة، العدالة، الجدوى، العقد المفحوصة، زمن التنفيذ بالمللي ثانية) ولا يمسّ المهام. ينتقل الدور إلى `Optimizing`.
3. **الاعتماد**: اختيار نتيجة واحدة — تُنشأ منها صفوف `cleaning_assignments` في نفس الصفقة (مع حذف أي مادية سابقة) فيصبح الدور `Approved`.
4. **التفعيل**: `Active` + إشعار (D6) لكل طالب مسند إليه («مهمة نظافة جديدة»).
5. **التنفيذ**: الطالب يبدأ مهمته ثم يُتمّها (توثيق زمني)، والضابط يستطيع «تخطي» مهمة (سبب خارجي). عند الإتمام يصل إشعار لمسؤول النظافة.
6. **الإكمال**: `Completed` — يُمنع بعدها أي تشغيل/اعتماد.

## 2. نموذج المسألة

- **المهام**: كل غرفة في الطابق = مهمة واحدة («تنظيف الغرفة X») لكل يوم من فترة الدورة.
- **الطلاب**: المقيمون في الطابق عبر تسكين نشط (D4) فقط (`RoomAssignment active` على غرف الطابق).
- **القيدان** (مشتركان للخوارزميتين): مهمة واحدة لكل طالب في اليوم، وحد أعلى لكل طالب `cap = min(ceil(T/M), عدد الأيام)`.
- **الجدوى**: يوم فيه مهام أكثر من الطلاب المقيمين، أو طابق بلا غرف/بلا مقيمين → `422` والسبب واضح.
- سقف المهام: 1000 مهمة للدورة الواحدة.

## 3. الخوارزميتان

| | BFS | A* |
|---|---|---|
| الطريقة | طبقة لكل يوم؛ في كل طبقة يأخذ الأقل تحميلاً مهام اليوم (طابور مفضَّل بالحمل) | بحث أمثل بمقاييس تقدير مسموحة: `h = ceil(المتبقي/M)` + حد التحدب `⌊المتبقي²/M⌋` |
| الضمان | حتمي ورخيص لكنه غير مُثبت الأمثلية | يُثبت الأمثلية لـ `(أقصى حمل، مجموع المربعات)` — لا يزيد أبداً عن BFS |
| القياس | عقد = عدد المهام | عقد = الحالات المفحوصة (سقف 200,000) |

المقاييس المخزنة لكل تشغيل: `total_cost` (أقصى حمل)، `fairness_score` (1 − (الأقصى−الأدنى)/المهام)، `feasibility_rate`، `nodes_expanded`، `execution_time`، و`result_summary` (JSON: المهمة→الطالب). الواجهة تعرض مقارنة مباشرة بين التشغيلين.

## 5. الأمان والتدقيق

- مصفوفة RBAC الثابتة: الضابط وحده يكتب الدورات، الطالب لا يلمس إلا مهمته (طلب غريب → 404 بلا كشف)، منع حالات خاطئة بـ409 (تشغيل بعد إكمال، إتمام مهمة معلقة…).
- أحداث `cleaning.*` (إنشاء/تشغيل/اعتماد/تفعيل/إكمال/بدء/إتمام/تخطي) في نفس الصفقة — التفاصيل معرفات فقط.

## 6. الواجهة

- **مسؤول النظافة**: صفحة «النظافة AI» — إنشاء دورة، جدول الدورات، حوار تفاصيل يعرض تشغيلَي BFS/A* بالمقاييس مع «اعتماد هذا الحل»، وأزرار التفعيل/الإكمال/التخطي.
- **الطالب**: صفحة «مهام النظافة» — يعرض مهامه مع «بدء التنفيذ» / «إتمام المهمة».
