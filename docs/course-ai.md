الموضوع: **نظام ذكاء اصطناعي لجدولة وتوزيع مهام نظافة الطوابق في سكن جامعي**
(المرجع في قائمة الأفكار الرسمية: «Smart Home Automation» / خدمات المنزل الذكي)

## 1) وثيقة الاقتراح — التسليم الأول (أسبوع 7)

> صفحة إلى صفحتين حسب تعليمات المادة — املأ أسماء أعضاء الفريق قبل الرفع.

**وصف المشروع:** السكن الجامعي يضم طوابق، كل طابق غرفاً بمستويات اتساخ مختلفة (بيانات
قاعدة بيانات النظام). يريد مسؤول النظافة توزيع الموظفين على المهام بحيث تُغطى كل غرفة
ضمن يوم واحد بأقل وقت/أقل تكلفة حركة. نبني **خوارزميتين** تحددان التوزيع الأمثل
وتقارنان أداءهما.

**خوارزميات الذكاء الاصطناعي (من تنفيذ الفريق، بلا أي API خارجي):**
- **BFS** — بحث أعمى يضمن إيجاد الحل إن وُجد (الأمثلية عند تكلفة موحدة).
- **A*** — بحث إرشادي بـ heuristic (عدد الغرف المتبقية × أصغر تكلفة تقديرية) يقلل
  حالات الاستكشاف مع الاحتفاظ بأمثلية الحل عند ضمان الاتساق.

كلا الخوارزميتين **جوهر حل المشكلة** (توليد جدول المهام)، وتُدار بنمط **Strategy**
وتقارن بمعطيات: عدد الحالات المفتوحة، النقاط الموسعة، زمن التنفيذ، تكلفة الحل.

**المعطيات:** طوابق/غرف/طلاب/دورات نظافة من قاعدة MySQL للنظام (لا يوجد نموذج تعلّم
آلي — خوارزميات بحث؛ فلا حاجة لمجموعة تدريب، والتقييم بـمقارنة خوارزميتين على نفس
البيانات).

**نوع الواجهة:** واجهة ويب عربية + عميل سطح مكتب (Tkinter) — كلاهما يقدّم «دورة النظافة»
ويستدعي `/api/v1/cleaning/*`.

**التقنيات:** Python 3.13، FastAPI، SQLAlchemy، MySQL/MariaDB، Tkinter، JWT، pytest.

**خطة تنفيذ موجزة:** البنية والبيانات (جداول طوابق/غرف/مهام) → تنفيذ BFS و A* في
`cleaning_ai.py` → تكامل REST (`/cycles`, `/optimize`) → مقارنة وقياس → واجهة الويب
والسطح المكتب → التوثيق والعرض.

**أعضاء الفريق (مجموعة من طالبين):**
- ياسر عبدالسلام الرزاقي
- شهاب الدين فهد رعدان

> ملاحظة: وفق شرط المجموعات (متطلب 9) تُطبَّق خوارزميتان مختلفتان — **BFS و A*** — حاضِرتان في الكود.

### توزيع مهام الذكاء الاصطناعي بين العضوين

**مبدأ التوزيع:** كل عضو يملك خوارزمية كاملة من البداية للنهاية (وهذا يحقق شرط
المتطلب 9 — خوارزميتان مختلفتان — ويكفل أن كل عضو يستطيع شرح عمله دفاعياً في
العرض)، مع إسناد طبقة تكامل واحدة (بيانات/واجهات/اختبارات) لكل عضو حتى يكون
الحمل متوازناً والإسهام التقني واضحاً.

| # | المهمة | المسؤول | التفاصيل (مرجع الكود) |
|---|---|---|---|
| 1 | صياغة المشكلة وانتقاء الخوارزميات | ياسر | صياغة هدف التحسين (تقليل أقصى حمل ثم توازن الأحمال)، تبرير BFS كخوارزمية أساس و A* كحل أمثل إرشادي |
| 2 | البيانات والمعالجة المسبقة | شهاب | استخراج الطوابق/الغرف/السكان من MySQL، تجميع المهام يومياً `_group_by_day`، فحص الجدوى `_feasibility_check`، حساب السقف `cap = min(⌈T/M⌉, أيام)`، مولّد حالات القياس |
| 3 | تنفيذ خوارزمية BFS | شهاب | `solve_bfs`: توسيع طبقي يوم بيوم، اختيار الأقل حمولة عبر الكومة `(load, order, sid)`، ضمان ثبات السقف، الحتمية |
| 4 | تنفيذ خوارزمية A* | ياسر | `solve_astar`: حالة التوازن `loads`، دالة التكلفة `g = max·10⁶ + Σ مربعات`، الإرشاد المقبول `h` (حد أدنى للمتبقي)، طابور الأولوية، حد العقد `200_000`، أمثولية الحل وإثباتها |
| 5 | التقييم ومقارنة الأداء | ياسر | قياس `nodes / elapsed / total_cost / fairness` للخوارزميتين على نفس الحالات، جداول المقارنة، وتحليل «تكلفة الأمثولية» |
| 6 | نموذج البيانات (MySQL) | شهاب | جداول النظافة (دورات، مهام، تشغيل، إسناد) في `app/models/cleaning.py` والهجرات |
| 7 | تكامل REST للذكاء | شهاب | مسارات `/cleaning/*` (إنشاء دورة، `optimize` بمعامل `algorithm`، الموافقة/التفعيل/الإكمال) |
| 8 | واجهة الذكاء (ويب + مكتبي) | شهاب | صفحة «النظافة AI» في البوابة (تشغيل ومقارنة BFS/A* وعرض الجدول) + تبويب المهام في عميل سطح المكتب |
| 9 | اختبارات الخوارزميات | ياسر | `tests/unit/test_cleaning_ai.py`: الجدوى، السقف، صحة الإسناد، أمثولية A* على حالات صغيرة مقابل بحث شامل |
| 10 | اختبارات التكامل | شهاب | `tests/integration/test_products_cleaning.py`: دورة حياة كاملة عبر REST على قاعدة حقيقية |
| 11 | تصميم OOP/SRP لوحدة الذكاء | ياسر | فئات `Task/Schedule/InfeasibleError`، نمط Strategy بين BFS وA*، فصل الخوارزميات عن قاعدة البيانات |
| 12 | وثائق الذكاء الاصطناعي | الاثنان | اقتراح أسبوع 7 (ياسر: أقسام الخوارزميات والتقييم؛ شهاب: البيانات والواجهات) + التقرير النهائي |
| 13 | العرض والتطبيق الحي | الاثنان | ياسر: شرح A* والنتائج؛ شهاب: شرح BFS والعرض الحي للواجهات |

**تناوب إدارة المشروع (يُدار بالتناوب كما تشترط المادة):**
- الأسابيع 1–4: ياسر منسقاً — خطة العمل، متابعة المهمتين 3 و4، حفظ السجلات.
- الأسابيع 5–8: شهاب منسقاً — متابعة التكامل والاختبارات ومواعيد التسليم.
- الأسابيع 9–11: الاثنان بالتناوب في المراجعة النهائية والرفع والعرض.

**أدوات التواصل وإدارة الإصدارات:** WhatsApp للمتابعة اليومية + GitHub (فروع ومراجعات) للتنسيق، كما في كل مراحل D1–D9 الموثقة.

**المراجع:** Russell & Norvig, *Artificial Intelligence: A Modern Approach* (الفصل الخاص
بالبحث الإرشادي)؛ التوثيق الداخلي `docs/cleaning-d9.md`.

## 3) هيكل التقرير النهائي (أسبوع 11)
استخدم بنية هذا الملف + `docs/cleaning-d9.md` + `docs/d9-results.md` لملء الأقسام:
1. نظرة عامة + المشكلة (§1).
2. المنهجية: البيانات، الخوارزميتان، لماذا كل منهما، البنية.
3. التنفيذ: الكود، البارامترات، المكتبات.
4. النتائج: جداول المقارنة + لقطات الشاشة (الويب + سطح المكتب).
5. التحديات والحلول (مثال حقيقي: تغيير مقارنة `role` من قيمة نصية إلى Enum — 403).
6. دليل المستخدم.
7. ملخص + أعضاء الفريق والأدوار.
