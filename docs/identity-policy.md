# D2 — سياسة الحسابات والصلاحيات والجلسات

## القرار المعتمد

اختار صاحب المشروع: **مسؤول النظام وحده ينشئ الحسابات ويحدد الأدوار، دون تسجيل عام.** لا تعني صلاحية إدارة الحسابات حق اتخاذ قرارات السكن أو قبول الطلاب أو اعتماد النظافة؛ تلك سياسات أعمال لاحقة.

## مصفوفة الصلاحيات المنفّذة

المستخدم المقصود هنا حساب نشط بجلسة صالحة. العمليات العادية تتطلب إتمام تغيير كلمة المرور إن كان مطلوباً.

| العملية | الطالب وبقية الأدوار غير مسؤول النظام | مسؤول النظام |
|---|---|---|
| عرض الحساب الحالي | حسابه فقط | حسابه |
| تعديل الاسم المستخدم والبريد ذاتياً | حسابه فقط | حسابه فقط |
| تغيير كلمة المرور | حسابه، مع الكلمة الحالية | حسابه، مع الكلمة الحالية |
| عرض/إبطال الجلسات | جلساته فقط | جلساته فقط من واجهة الجلسات الذاتية |
| إنشاء حساب وتحديد دوره | ممنوع لبقية الأدوار | مسموح |
| عرض قائمة الحسابات أو حساب بمعرف | ممنوع لبقية الأدوار؛ يستعملون users/me | مسموح |
| تعديل دور/نشاط حساب آخر | ممنوع | مسموح مع إبطال جلسات الهدف |
| إعادة تعيين كلمة مرور حساب آخر | ممنوع | مسموح، مع إبطال الجلسات وفرض تغييرها |
| قراءة سجل أحداث الهوية | ممنوع | مسموح |
| حذف حساب نهائياً | غير متاح | غير متاح |
| تغيير المدير لدوره/نشاطه | غير متاح | ممنوع حتى لا يقفل وصوله بالخطأ |

الأدوار التسعة ثابتة: Student، Housing Administration، Student Affairs، Maintenance Officer، Activity Officer، Cleaning Officer، Food Officer، Sports Officer، System Administrator.

الخدمات العامة الجديدة تفرض السياسة، ومسارات HTTP لا تعرض مخططات الكتابة الداخلية دون تفويض. المستودعات وSession/SQL أدوات داخلية موثوقة وليست حدود صلاحيات مستقلة؛ لا تُنشئ مساراً جديداً يستقبل dict ويكتب مباشرة عبرها.

## أول مدير وحسابات المستخدمين

بعد تطبيق الهجرات:

```text
python -m tools.bootstrap_admin --username YOUR_ADMIN --email you@example.com
```

- تُطلب كلمة المرور مرتين بواسطة getpass؛ لا كلمة مرور افتراضية ولا طباعة لتوكن أو كلمة مرور.
- للأتمتة المصرح بها فقط يوجد `--password-stdin`، ويقرأ سطراً واحداً من stdin. لا تمرر السر في وسيطات سطر الأوامر ولا تحفظه في ملف مصدر.
- الأداة لمرة واحدة: ترفض إذا وُجد حساب يحمل دور System Administrator، حتى لو كان غير نشط.
- عمليتا bootstrap متزامنتان لا تنشئان مديرين؛ قفل صف `account_guard` يستمر حتى commit.
- أول مدير يختار كلمته بنفسه فلا يُفرض عليه تغييرها فوراً. الحسابات المنشأة من API بواسطة المدير وإعادات التعيين تُفرض عليها `must_change_password=True`.
- عند وجوب تغيير الكلمة يُسمح بالدخول لعرض الحساب وتغيير الكلمة وإدارة الخروج/جلساته، لكن تُمنع عمليات الملف العادية والإدارة إلى أن يغيرها.
- تغيير الكلمة يتطلب الكلمة الحالية وكلمة جديدة مختلفة. بعد النجاح تنتهي كل الجلسات، ويجب تسجيل الدخول بالكلمة الجديدة.

إن وُجد مدير سابق لا يستطيع الدخول، فـbootstrap ليست باباً خلفياً لتجاوز الحساب. يلزم إجراء استعادة مُصرَّح ونسخة احتياطية؛ لم تُضف هذه الدفعة مسار استرجاع مجهول أو استرجاع بالبريد.

## واجهات API

جميع المسارات التالية تحت `/api/v1`، وتستعمل Bearer tokens ما عدا تسجيل الدخول.

| الطريقة | المسار | الوظيفة |
|---|---|---|
| POST | `/auth/login/access-token` | username/password بصيغة form؛ لا JSON |
| GET | `/auth/users/me` | الحساب الحالي |
| PATCH | `/auth/users/me` | username/email فقط؛ لا role أو is_active أو password_hash |
| POST | `/auth/change-password` | current_password/new_password؛ ثم إبطال الكل |
| POST | `/auth/logout` | إبطال الجلسة الحالية |
| POST | `/auth/logout-all` | إبطال كل جلسات صاحب الطلب |
| GET | `/auth/sessions` | الجلسات غير الملغاة وغير المنتهية لصاحب الطلب |
| DELETE | `/auth/sessions/{session_id}` | إبطال جلسة يملكها صاحب الطلب، دون حذف سجلها |
| POST | `/users` | إنشاء إداري؛ username/email/password/role، وis_active اختياري |
| GET | `/users` | قائمة إدارية بترتيب ثابت وصفحات |
| GET | `/users/{user_id}` | عرض إداري |
| PATCH | `/users/{user_id}` | username/email/role/is_active؛ لا تعديل مباشر للهاش أو auth_version |
| POST | `/users/{user_id}/reset-password` | new_password؛ لا يجوز للمدير استعمالها على حسابه |
| GET | `/audit-events` | سجل أحداث الهوية للمدير |

مع العمليات العامة `/` و`/health` و`/ready` يصبح المجموع 17 عملية تطبيقية. لا تُحتسب Swagger/Static ضمنها. لا يوجد `DELETE /users/{id}` ولا تسجيل عام.

حد الصفحة 1–100، والإزاحة 0–100000. معرّفات المسارات UUID. لا يُكشف هاش كلمة المرور أو auth_version في استجابة الحساب. أوقات الاستجابات تحمل UTC بعلامة Z، واستجابات API تحمل `Cache-Control: no-store`.

## JWT والجلسات

- PyJWT مع HS256 فقط؛ لا يُقبل اقتراح خوارزمية من التوكن.
- حقول exp/iat/sub/jti/ver/type/iss/aud إلزامية؛ النوع access، والجمهور والجهة المصدرة مطابقان للإعدادات.
- التوقيع الصحيح وحده لا يكفي: يجب وجود `auth_sessions` مطابق للمستخدم والإصدار والوقت وغير ملغى، والمستخدم نشط.
- التفويض يستعمل الدور الحالي في قاعدة البيانات، لا ادعاء الدور داخل JWT.
- الافتراضي 30 دقيقة؛ الإعداد يسمح 1–60. **القيمة القديمة 1440 في ملف .env يجب تغييرها.**
- الافتراضي خمس جلسات نشطة؛ إصدار جلسة إضافية يُبطل الأقدم. لا refresh tokens في هذه النسخة.
- تغيير كلمة المرور أو دور الحساب أو حالة نشاطه يُبطل كل جلساته. إعادة تفعيله لا تعيد صلاحية التوكنات القديمة.
- الإبطال يرفض الطلبات اللاحقة؛ لا يعني إلغاء طلب أنهى التحقق وبدأ التنفيذ بالفعل. الكتابات الحساسة تعيد التحقق بعد القفل لتقليل سباقات الصلاحيات.
- كل توكن D1 سابق غير صالح بعد الانتقال إلى D2؛ يلزم تسجيل الدخول مجدداً.

## سياسة كلمات المرور

الكلمات الجديدة/المعدلة 12–256 محرفاً صالحاً بـUTF-8 وبحد 1024 بايت. لا قص أو تطبيع أو إزالة مسافات خفية. الكلمات المخزنة سابقاً لا يُعاد تعيينها أثناء الهجرة، ويمكن التحقق منها وفق مسار التوافق.

Argon2id للهاشات الجديدة، والتحقق من bcrypt القديم محدود بـ72 بايت، مع إعادة تهشير عند دخول نشط صحيح. الحساب القديم ذو كلمة bcrypt أطول يحتاج إعادة تعيين إدارية؛ لا نقبل بادئتها فقط. لا يُطبع السر في repr لمخططات كلمات المرور أو التوكن أو إعدادات أسرار الاتصال.

هذه حدود طول، وليست ضماناً لقوة أي كلمة مختارة. MFA وسياسة الكلمات الشائعة واسترجاع الحسابات خارج نطاق D2 الحالي.

## محاولات الدخول

عدادات ثابتة النوافذ في MariaDB، وليست قاموساً محلياً يضيع عند تعدد العمليات أو إعادة التشغيل:

- افتراضياً 30 محاولة لكل عنوان مصدر خلال 60 ثانية.
- و8 محاولات لكل زوج (الحساب، عنوان المصدر) خلال 300 ثانية، بما فيها المحاولات الناجحة.
- للحساب المعروف يُستعمل UUID بعد البحث، كي لا تتجاوز اختلافات حالة الأحرف في اسم المستخدم حد الحساب نفسه.
- لا قفل عالمي للحساب من مصدر آخر؛ يستطيع المهاجم من شبكة أخرى استهلاك حصته لا حصة صاحب الحساب من عنوان مختلف. ليست هذه حماية كافية وحدها من هجوم موزع.
- يوجد حد منفصل لمحاولات تغيير كلمة المرور: خمس لكل (المستخدم، المصدر) خلال 300 ثانية.
- العدّاد يُحفظ في معاملة مستقلة حتى لو رجع طلب الدخول 401 وتراجعت معاملته الرئيسية. التحديث ذري بين الاتصالات/العمال.
- التجاوز يرجع 429 وRetry-After. تعطل مخزن الحماية لا يسمح بتجاوزها؛ يرجع خطأ خدمة مؤقت.
- اسم غير موجود يمر بعملية تحقق Argon2id وهمية لتقليل فرق التوقيت. هذا ليس ادعاءً بتوقيت متطابق تماماً، خصوصاً للحسابات ذات الهاشات القديمة.
- لا نقرأ X-Forwarded-For من العميل مباشرةً. إذا وضعت reverse proxy فاضبط قائمة الوكلاء الموثوقين في خادم ASGI، ولا تثق بكل العناوين.
- اضبط حدود المصدر وفق عدد مستخدمي السكن خلف NAT واحد، وقِس أثرها قبل النشر.

المفاتيح المخزنة HMAC بمفتاح التطبيق مع فصل النطاق؛ لا تخزين لاسم المستخدم أو عنوان IP الخام في العدّادات. تدوير SECRET_KEY يبطل التوكنات ويغيّر مفاتيح العدادات.

تنظيف العدّادات المنتهية عملية صريحة:

```text
python -m tools.prune_login_limits
python -m tools.prune_login_limits --apply
```

الأول معاينة، والثاني يحذف المنتهي فقط. جدولة الأمر مسؤولية التشغيل؛ لا توجد خدمة جدولة عاملة تلقائياً. لا يحذف الأمر سجلات التدقيق أو الجلسات.

## السجل والاحتفاظ

- تُسجّل عمليات إنشاء/تعديل الحسابات وتغيير/إعادة تعيين الكلمات والدخول الناجح والفاشل وإبطال الجلسات والتهيئة الأولى.
- تُسجّل الكتابة الإدارية وحدثها في معاملة واحدة: فشل كتابة الحدث يلغي التغيير.
- فشل الدخول يُسجّل مستقلاً بمفاتيح pseudonymous حتى لا يختفي مع rollback.
- التفاصيل allowlist محدودة؛ لا كلمات مرور أو توكنات أو قيم البريد/الملف الشخصي.
- لا واجهة لتعديل/حذف الأحداث، وORM يرفض تحديث AuditEvent أو حذفه.
- حذف المستخدم نهائياً مرفوض في خدماته ومستودعه، ولا يوجد له مسار HTTP. تعطيله لا يمحو ملف الطالب أو تاريخ حالاته.
- هذا **ليس** سجلاً محصناً ضد مسؤول DB ذي الصلاحيات الكاملة أو SQL مباشر. استخدم مستخدم DB بأقل الصلاحيات الممكنة، وقيّد الوصول الإداري والنسخ الاحتياطية.
- روابط CASCADE القديمة لسجلات الطالب لم تُغيّر. لا تُنشئ خدمات حذف طلاب لاحقاً دون مراجعة سياسة الاحتفاظ.
- لا حذف تلقائي لسجلات الأحداث والجلسات في D2؛ مدة الاحتفاظ/الأرشفة/المحو ما زالت قراراً مطلوباً قبل النشر، وليست توصية بالاحتفاظ إلى الأبد.

## التزامن والجاهزية

قفل `account_guard` يسبق قفل المستخدمين والجلسات في العمليات الإدارية. لا يستطيع المدير تغيير دوره أو نشاطه بنفسه، وتوجد حماية للمدير النشط الأخير. الطلبات المتعارضة يمكن أن ترجع 409 مع إلغاء العملية؛ أعد قراءة الحالة قبل إعادة المحاولة، ولا تكرر طلب إنشاء دون تحقق.

`/health` يبقى فحص اتصال. `/ready` يتحقق من إصدار المخطط وصف القفل وأعمدة/جداول الهوية الأساسية. لا يُعلن جاهزاً عند غياب الهجرة المطلوبة، لكنه ليس فحص حمل أو نسخة احتياطية أو ضماناً لاكتمال خدمات السكن.

## حدود هذه الدفعة

إدارة حساب يحمل دور Student ليست إنشاء ملف الطالب أو طلب سكن. الواجهة العربية ودورات الطلبات والمستندات والغرف وقرارات الموظفين وAI ما زالت لاحقة. لا HTTPS أو reverse proxy أو MFA أو نسخ احتياطي عاملة تلقائياً ضمن هذا المستودع. لا تعتبر D2 وحدها موافقة على تشغيل بيانات حقيقية.
