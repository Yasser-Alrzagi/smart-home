# تسليم D3 — من ملف الطالب إلى قرار السكن

**الحالة: نُفّذت واختُبرت محلياً في 6 سبتمبر 2026. لم تُرفع هذه الدفعة إلى GitHub بعد.**

الأساس هو `main` عند `249bc912dcefa1a1cfdbc208659117976d50cd81`، بعد دمج D1 وD2. العمل في فرع محلي مستقل `feat/student-applications`، دون تعديل قاعدة بيانات صاحب المشروع.

## القراران المنفّذان كما اخترتهما

- شؤون الطلاب تراجع وتتحقق من المستندات، ثم تحيل إلى إدارة السكن للقرار النهائي.
- الهوية الوطنية وإفادة القيد إلزاميتان؛ البطاقة الجامعية اختيارية، ما لم يطلبها المراجع تحديداً للاستكمال.

## ما أصبح متاحاً؟

1. إنشاء وتحديث ملف الطالب الذاتي مع منع تغيير الحقول الإدارية أو الكتابة باسم طالب آخر.
2. مسودة طلب، ورفع/استبدال/إزالة مستندات في الحالات المسموحة، ثم تقديم الطلب.
3. طلب استكمال مع سبب وقائمة مستندات، وإعادة تقديم دون تجاوز المراجعة.
4. مراجعة شؤون الطلاب ثم الإحالة إلى إدارة السكن؛ قبول/رفض أو إعادة للمراجعة وفق قواعد واضحة.
5. قفل الحالات النهائية، وتجميد بيانات الطالب داخل الطلب، وأرقام نسخ تمنع الكتابة على نسخة قديمة.
6. تنزيل محمي ومحدود للمستندات، دون روابط عامة أو كشف مسار تخزين.
7. سجل مراحل وملاحظات وأدوار؛ وفشل كتابة السجل يلغي التغيير في العملية نفسها.
8. واجهة عربية RTL فعلية للطالب والمراجعين، مع واجهة أولية للحسابات والأمان. الملفات محلية دون CDN.

**القبول لا يخصص غرفة.** الملفات الجديدة تبدأ بوصف Applicant، وتوزيع الغرف ونقل الطلاب هما D4. النظام الكامل والخدمات والذكاء الاصطناعي لم يكتمل بعد.

## حماية المستندات وحدودها

المستندات في DB كـMEDIUMBLOB، لا في مجلد static. تُحفظ مع البيانات والسجل في معاملة واحدة، ومحتواها غير موجود في JSON. التنزيل يتحقق من الصلاحية والحجم والبصمة ويرجع attachment/no-store/nosniff.

الحد الافتراضي 5 MiB لكل ملف، مع PDF/JPEG/PNG فقط. تُزال بيانات الصور الوصفية عند إعادة الترميز، وتُرفض PDFs المشفرة أو التفاعلية/النشطة والملفات المزيفة. توجد حدود صفحات/بكسلات/وقت وموارد للتحقق.

**هذا ليس فحص فيروسات أو إثبات أصالة مستند، وليس عزلاً أمنياً كاملاً للعملية الفرعية.** محتويات DB غير مشفرة على مستوى التطبيق؛ يلزم تشفير التخزين والنسخ الاحتياطية وTLS وضبط الصلاحيات قبل استقبال وثائق حقيقية. سياسة الاحتفاظ بنسخ المستندات والمحو الرسمي لم تُعتمد بعد؛ استبدال ملف في المسودة أو الاستكمال لا يؤرشف نسخته القديمة كاملة.

## الواجهة وطريقة فتحها

بعد تطبيق الكود، وتثبيت الاعتماديات، وترقية قاعدة تجريبية:

```text
python -m pip install --require-hashes -r requirements.txt
alembic upgrade head
python main.py
```

افتح **http://127.0.0.1:8000/app** على جهاز التشغيل. استخدم حساب المدير الموجود، أو أداة bootstrap لأول مدير فقط. من حساب المدير أنشئ حساب طالب وشؤون طلاب وإدارة سكن لتجربة الدورة.

لا توجد حسابات افتراضية أو كلمات مرور إنتاجية في التسليم. صور الواجهة المرفقة من اختبار حقيقي ببيانات اصطناعية، لا صور تصميم مولّدة. التوكن في ذاكرة الصفحة فقط؛ تحديث الصفحة يتطلب دخولاً جديداً.

## تغييرات يجب معرفتها قبل الترقية

- الهجرة الجديدة `d3b7a21c8f04` بعد D2، والإجمالي **27 جدولاً و29 عملية API**، إضافة إلى مساري الواجهة `/app` و`/app/`.
- ملفات الهجرتين السابقتين بقيت مطابقة بالبايت لنسخة main الأساسية.
- إذا كانت المستندات القديمة مكررة للنوع نفسه، تتوقف الترقية للمراجعة بدلاً من حذف بيانات.
- المسارات القديمة في file_path لا تُستخدم لقراءة ملفات القرص؛ يلزم إعادة رفع المستند عبر المسار المحمي.
- التراجع عن D3 يرفض وجود بيانات D3 التي قد تُفقد، وتوليد SQL للتراجع دون اتصال معطل. لا تستبدل النسخ الاحتياطية بأمر downgrade.
- أُضيف اختبار Chromium إلى CI على Python 3.13، ورُقيت أدوات Actions إلى Node 24 مع تثبيت commits رسمية. **فحوصات D3 على GitHub لم تعمل بعد**؛ ستعمل عند رفع الفرع الجديد.
