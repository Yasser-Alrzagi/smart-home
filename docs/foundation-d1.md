العمل مبني على الالتزام `507615e5d9a4a3312a760c6d44075fe157601b26`، في فرع محلي اسمه `fix/foundation`. لم يُرفع شيء إلى GitHub ولم تُستخدم قاعدة بيانات صاحب المشروع. قواعد التجربة محلية ومعزولة، وجميع الحسابات فيها اصطناعية.

## 3. اختبارات مهمة أضيفت

- كلمتان تختلفان بعد أول 72 بايت لا تتطابقان، بما في ذلك كلمات عربية.
- نجاح تسجيل الدخول و`users/me` عبر HTTP دون كشف الهاش.
- تحديث هاش bcrypt القديم إلى Argon2id وحفظه فعلياً بعد دخول صحيح لحساب نشط.
- الحساب المعطّل لا تُغيّر كلمة مروره أثناء محاولة الدخول.
- التغيير الناجح يبقى عند القراءة من اتصال جديد.
- الفشل بعد كتابة جزء من العملية يلغي ذلك الجزء.
- فشل commit المتأخر لا يتحول إلى استجابة HTTP نجاح مبكرة. الاختبار يستعمل تطبيقاً تجريبياً، ولم يُضف مسار كتابة عام إلى التطبيق الحقيقي.
- التحقق من أن كل اعتماد DB في مسارات التطبيق الحالية يستخدم نطاق function.
- التواريخ/الطلبات/التوزيع ليست ضمن هذه الاختبارات الجديدة؛ خدماتها لم تُنفّذ بعد.
- رفض عنوان قاعدة اختبار غير آمن دون إعادة كلمة مروره في رسالة الخطأ.
- إثبات عدم قراءة ملف `.env` اصطناعي غير صالح في وضع الاختبار.
- اكتشاف قيمة تعداد خاطئة في التوثيق، لا الاكتفاء باسم النوع.
- التأكد من أن أداة التوليد التاريخية لا تستطيع الكتابة فوق الهجرة المصححة.

## 4. تغييرات يجب أن تعرفها قبل الاستخدام

### كلمات المرور

كلمات المرور الجديدة/المعدلة: 8–256 محرفاً صالحاً بـUTF-8، بحد 1024 بايت. لا قص ولا تطبيع ولا إزالة مسافات خفية. Argon2id مضبوط حالياً على 64 MiB وثلاث دورات وأربع مسارات؛ ضبط الحمل ومقاومة المحاولات المتكررة جزء لاحق، وليس ضماناً لتحمل ضغط غير محدود.

دعم bcrypt القديم لا يقبل كلمة مرور تزيد على 72 بايت. كلمة قديمة أطول تحتاج إعادة تعيين؛ لا يمكن استعادة الجزء الذي تجاهله bcrypt من الهاش القديم. لا توجد في D1 واجهة أو API لإعادة التعيين. الحسابات الجديدة لا تستخدم bcrypt، وPasslib أزيل من اعتماديات التشغيل.

### المعاملات

في مسارات HTTP الجديدة استخدم `DatabaseSession` من `app.core.database`، لا `Depends(get_db)` بنطاقه الافتراضي. هذا مهم حتى يقع commit قبل إرسال النجاح. للمهام والسكربتات استخدم `session_scope()` للمعاملة الكاملة. لا تمرر الجلسة المغلقة إلى مهمة خلفية أو بث مستمر؛ أنشئ جلسة مستقلة هناك.

### التحديث الجزئي

عدم إرسال الحقل يعني إبقاءه. إرسال `null` لاسم المستخدم أو البريد أو كلمة المرور أو الدور أو النشاط أصبح خطأ تحقق متعمداً، لأن تلك الحقول لا تدعم التفريغ. هذه المخططات ما زالت داخلية؛ مسارات إدارة الحسابات وسياسات إدخال الطالب ستُبنى في D2.

### الاختبارات والهجرة

`pytest` العادي لا يحتاج قاعدة تشغيل أو ملف `.env`، لكنه يتخطى اختبارات DB عند غياب إعدادها. للحصول على نتيجة كاملة، جهّز قاعدة اختبار منفصلة كما يوضح README، ثم:

```text
python -m pip install --require-hashes -r requirements-dev.txt
python -m tools.test_database
python -m pytest -q
```

الأمر الثاني يتطلب `TEST_DATABASE_URL` مسموحاً يشير إلى قاعدة موجودة خصيصاً للاختبار. دورة التراجع المدمرة تتطلب إعداداً إضافياً لقاعدة scratch منفصلة فارغة و`RUN_MIGRATION_CYCLE=1`. **لا تشغل downgrade على بيانات تريد الاحتفاظ بها.**

## 5. ما بقي خارج الدفعة الأولى؟

لا تزال هذه الأعمال مطلوبة ولا ندعي إصلاحها:

- أداة إنشاء أول مدير ومسارات إدارة الحسابات والطلاب.
- مصفوفة الصلاحيات وملكية السجلات، ومنع الطالب من تعديل دور أو بيانات غيره.
- rate limiting ومقاومة تعداد الحسابات وسياسة الجلسات وإبطال التوكنات بعد تغيير كلمة المرور.
- صرامة عقد JWT بالكامل؛ التوكنات الصادرة لها انتهاء لكن اشتراط حقولها عند الفك ضمن D2.
- سياسة حذف/أرشفة الطلاب وسجلهم؛ علاقات CASCADE بقيت كما هي، ولا يوجد مسار حذف عام جديد.
- قيود أهلية السكن والسعة والتواريخ وانتقالات الحالات والتزامن في التوزيع.
- الواجهة والمستندات ودورات الطلبات والخدمات والشكاوى والغياب.
- BFS وA* وتعريف العدالة واعتماد نتائج النظافة.
- readiness الكامل، وإعداد نشر إنتاجي، ونسخ احتياطي وتجربة استعادة.

إعداد CORS أصبح يرفض النجمة والقائمة الفارغة، لكن ذلك لا يعني اكتمال تقوية إعدادات الإنتاج. `/health` ما زال فحص اتصال فقط.

## 6. الاعتماديات الأمنية

فحص الاعتماديات المقفلة سجل تنبيهاً واحداً في `ecdsa==0.19.2` مرتبطاً بـCVE-2024-23342. المصادقة الحالية تستعمل HS256، ولم نثبت قابلية استغلال التنبيه في هذا المسار. التنبيه **لم يُخفَ أو يُعتبر مُصلحاً**؛ مراجعة مكتبة JWT وسلسلة اعتمادياتها باقية في D2.

`pyproject.toml` مصدر تعريف الاعتماديات، و`uv.lock` هو القفل، وملفا requirements صادران عنه مع hashes. البيئة المرجعية استعملت uv 0.12.10. لا تعدّل ملفات التصدير يدوياً، ولا تعتمد على بقايا بيئة التطوير القديمة؛ جرّب بيئة جديدة كما جرى في اختبار Python 3.12.

## 7. نطاق التغييرات والمحافظة على الموجود

حُفظ التغيير المحلي السابق في `_offline_head.sql` كما وجدناه؛ كان متعلقاً بعلامة BOM، ولم نضمه إلى رقعة الإصلاح. لم يُمسّ أي سر إنتاج ولم يُنشأ ملف `.env` حقيقي في التسليم.

حُفظ المصدر السابق لأداة `_assemble_revision.py` في `alembic/superseded/assemble_revision_legacy.py.txt`؛ الأداة الجذرية الآن ترفض إعادة التوليد. الملفات النصية القديمة ليست هجرات نشطة، ولا تعني رسالة Multiple heads التاريخية وجود أكثر من رأس الآن.
